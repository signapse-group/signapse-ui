## Local verification

The focused component checks use deferred supplement responses, failures/retries and out-of-order asset/timeframe/filter responses. They cover immediate valid candles, independent annotation/calendar status, stale-response guards, the active candle response surviving URL sync while a prior candle response remains ignored, and sparse 1h backfill with one received 07:00 candle: annotations query `[07:00,10:00)`, calendar history query `[07:00,08:00)`, the 09:00 annotation is merged, and the 10:00 boundary annotation appears once with its source timestamp. A rapid HIGH → HIGH+MEDIUM → MEDIUM filter change confirms that the final request covers every selected impact and stale responses do not add events.

The same controlled component fixture records the time from the candle response resolving until the candle DOM marker is visible while both supplemental promises remain pending. A matched local run on the original base `3278deb69bc417da5dfbc2681e8d75046a909cd9` and candidate `fb4a78f6e7dc869d081728bdf3a114b495f4fbda` measured **203.8 ms** and **38.6 ms**, respectively. After rebasing onto current `origin/dev`, the same fixture measured **45.0 ms** before the footer correction and **22.0 ms** on the corrected candidate; the standalone rerun after the URL-sync fix measured **20.7 ms**. A second run concurrent with typecheck, lint and contract checks measured **51.6 ms** and is not comparable because those checks competed for local resources. These runs reported `supplements_pending_at_paint=true`; the standalone 20.7 ms result is a repeat observation, not a controlled comparison or a claim that the URL-sync fix improved initial-load latency. Each figure is a single JSDOM/component-fixture observation, not browser paint or production latency; the original pair is not a repeated median and does not establish a live dev improvement. No latency threshold was applied.

## API reference and limits

The published dev OpenAPI at `https://dev-api.signapse.cloud/v3/api-docs` was fetched on **2026-11-20 08:53 UTC**, producer revision `765059683b3b265ce101823765d9cc5f9495e0f4`. Candle count-back uses an exclusive `to`; the response returns candles chronologically and may be empty or end with a partial candle. Annotations return the complete matching result in `[from,to)` without pagination and preserve source timestamps. Economic-calendar history uses `[from,to)` and supports repeated impact filters. All three operations require `MARKET_CHART_READ` (`market-chart:read`). The consumer still matches the published contract; no producer or business contract change was made.

No live feature test or dev before/after measurement was performed. The coordinator owns live dev checks and five-run, cache-separated measurements for opening the chart, changing asset and changing timeframe, plus realtime, event-layer, rapid-selection and annotation-backfill checks. The coordinator decides whether the observed improvement is sufficient. First-candle readiness still depends on the candle endpoint response and chart rendering, so provider latency remains unmeasured. Native browser zoom was unavailable in the headless runner; the coordinator can verify it in a desktop browser if needed.

Current-head `Verify / check` and Vercel Preview must pass before In Review. The reviewer owns merge, dev delivery and live revision verification.
